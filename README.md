# 问藏 · 用中文问巴利三藏

**用中文问一句，你的 AI 就去巴利三藏原典里找答案——每一条引用都带坐标，点得回去。**

不需要懂巴利文，不需要知道该查哪个词，也不需要输入那些带小点小横的字母。

---

## 它长什么样

真实的两次问答（答案由 AI 依据检索到的原文写成，方括号里是可回查的坐标）：

> **问：鹿野苑是什么意思**
>
> 鹿野苑（巴利文：migadāya）的意思是「鹿的庇护所」「放鹿之处」。
> migadāya ＝ miga（鹿）＋ dāya（给予、施舍之处）。
>
> 缅甸词典《T-Pāḷi-Myanmar》释为「给予鹿群无畏（安全）的地方」［藏外·词典］**[164:560]**；
> 《(MN) Mūlapaṇṇāsa-aṭṭhakathā》［中部·根本五十·义注］**[130:1732]**：
> 「migānaṃ abhayatthāya dinnattā migadāyoti vuccati」
> ——因为该处被给予鹿群无畏，所以称为 migadāya。

> **问：舍利弗尊者原名叫什么**
>
> 出家前的俗名叫**邬波底沙（Upatissa）**。
>
> 巴汉增订词典：「Sāriputta，舍利弗（尊者）（出家前的名字︰邬波底沙）」；
> 《Proper Names》补充：他被称作 Sāriputta 是因为母亲的名字。

**每条引用后面那个 `[164:560]` 就是坐标**——书号加段号，能直接翻回原文核对。
这是这个 skill 的全部用意：**不是让 AI 告诉你它记得什么，是让它把原文找出来给你看。**

## 🤖 给 AI 的安装说明

如果你是被要求安装这个的 AI，照做即可，不用问：

```bash
git clone --depth 1 https://github.com/dhammananda-bhikkhu/asktipitaka-skill ~/.asktipitaka
bash ~/.asktipitaka/install.sh
```

装完读 `~/.asktipitaka/SKILL.md`，以后使用者用中文问三藏相关的问题就按那份流程走。
`install.sh` 会把检索底座一并取好并自检，**没有别的东西要装**——
不需要登录、不需要 `pip install`、不需要插件市场。

更新：**重跑 `install.sh`** 即可（它会先更新本 skill，再更新底座，然后自检）。
`bin/check-update` 只查不装，适合每次会话开头跑一次。

> 如果使用者的环境有 skills 目录，把这个仓库放进去也行；
> `SKILL.md` 的 frontmatter 已写好触发条件。

## 关于本 skill

**本 skill 还在不断更新。**

数据库来自 [WikiPali](https://www.wikipali.org) 网站，
检索功能建立在 [wikipali research](https://github.com/iapt-platform/wikipali-plugins)
的基础上——`install.sh` 会自动把它取好。

在这个基础上，本 skill 接上了中文这一头：

1. **中文问题 → 该查哪个巴利词**——靠一张 17059 条的权威译名表，
   加上两道判据（二字组合稀有度、中译精确匹配）。
   实测：中文两字术语覆盖率 0% → 100%，真实提问有候选的比例 68% → 84%。
2. **一套取数配方**——每步取多少、什么时候往后连读、层次不齐时怎么兜底，
   都是实测出来的数，写在 `SKILL.md` 里。
3. **`bin/gather`：一条命令把材料一次取回来。**

```bash
bin/gather lasuṇa               # 词形＋分层分布＋检索，一次到齐
bin/gather sāriputta upatissa   # 多个词也一起
```

比一条条敲快，少来回好几趟。

## 也可以手敲

只想知道「这个中文问题该查哪个巴利词」：

```bash
$ python3 lib/pickwords.py "有一个名字叫荤腥的外道吗"
候选（越靠前越可能是这题要查的；最终选哪几个由你定，最多 4 个）：
  bāhiraka                         外道
  titthiya                         外道
  āmagandhasutta                   《荤腥经》
  nāmapaññatti                     名字概念
```

检索也可以，`bin/wp` 就是底座的入口：

```bash
bin/wp forms parivāsa                      # 展开词形（永远的第一步）
bin/wp dist --lemma parivāsa               # 看本文/义注/复注怎么分布
bin/wp search --lemma parivāsa --limit 40  # 检索
bin/wp get 141:63                          # 按坐标取原文
```

## ⚠️ 这一版请先知道这三件事

**一、坐标没有经过机器核验。**

网页版在给出答案前还有一道**由代码执行**的核对——逐条验证引用是否真的出自
那一段，核不过的坐标直接摘掉。**这一版没有这一道。**

> **引用之前请自己点开坐标核对一遍**，尤其是**经名、人物、故事出处**这三类。
> 实测这三类最容易错。

为什么不干脆写成「请 AI 核对一下」：那道核对之所以有用，**正因为它是代码，
不是叮嘱**。模型写答案，错误是概率性的；代码做核对，结果是确定性的。
写成叮嘱就退化成又一个概率性步骤，保证就没了。
**它会在后续版本里以脚本形式补上。**

**二、书名表是快照，可能过期。**

`data/` 里的书名与层次表是本包自带的静态快照，**过期是必然的**——
它是某个时点导出的文件，而语料是活的。
所以 `SKILL.md` 规定：**书名与层次一律以实时输出为准，静态表只在实时没给时补位。**
表里没有的书由 `lib/booknames.py` 从巴利书名推中文标注，推不出就写
「层次未标注」——**绝不默认「根本」**。

**三、变音符号的拼写纠错也没有。**

网页版会从语料反查改正拼错的变音符号（`bhīsakka` 全语料 1 句，
`bhisakka` 42 句——差一个长音符整题就废）。本版靠 `SKILL.md` 的铁律提醒 AI
「查到 0 条先怀疑拼法」，**是叮嘱不是保证**。

## 反馈

⚠️ **这个 skill 跑在你自己的机器上，我们收不到任何使用数据**——
哪里答砸了、哪个词选错了，**除非你说，否则不会有人知道**。

所以如果答得不对，很欢迎告诉我们，哪怕只是把问题和答案原样贴过来：

- **邮件**：feedback@asktipitaka.org
- **GitHub**：在本仓库提 issue

答错的例子对我们特别有用——网页版的每一次改进，几乎都是从一道答砸的题开始的。
